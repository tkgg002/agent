## Root cause — 5 bug độc lập
1. **V1 vs V2 repo lệch**: worker query
   `cdc_system.cdc_mapping_rules` (V1, đã không còn ai ghi). CMS/FE ghi
   vào `cdc_system.mapping_rule_v2` (V2). 18 rule active V2, 0 rule V1
   → "no active mapping rules".
2. **Sai DB connection**: sau khi tìm được rule, build UPDATE và exec
   trên `h.db` (port 5434 destination plane `goopay_dest`). Schema
   `shadow_centralized_export_service` chỉ tồn tại ở `h.shadowDB`
   (port 5436 `cdc_shadow`). Cùng bug pattern với fix sáng cùng ngày
   `FixAlterColumnShadowSchema`.
3. **PG identifier case-folding**: column shadow là `"exportType"`
   (mixed case, được tạo bởi `quoteCommandIdent` ở handler ALTER).
   Builder transform dùng bare `exportType` → PG fold lowercase →
   `column "exporttype" does not exist`.
4. **JSONB cast sai operator**: rule `params` có `data_type=JSONB`,
   shadow column `params jsonb`. `buildCastExpr` không có nhánh JSONB,
   fall-through `default` → `(_raw_data->>'params')::TEXT`. Operator
   `->>` trả TEXT, gán vào JSONB column → 42804.
5. **Epoch-ms timestamp**: Mongo BSON Date được Debezium serialize
   thành JSON number (`1778482050803`). `(_raw_data->>'createdAt')`
   trả text `"1778482050803"`. PG `::TIMESTAMP` parse text → tưởng là
   YYYYMMDD format → `timestamp out of range` 22008.

## Lessons (đề xuất append vào `agent/memory/global/lessons.md`)

### Pattern 1 — V1/V2 repo split (source-of-truth divergence)
> **Global Pattern**: `Hệ thống có 2 generation table (A_v1, A_v2). Writer
> migrate sang A_v2 nhưng Reader X vẫn query A_v1 → X trả 0 row dù dữ
> liệu thực tế tồn tại`. Đúng: khi migrate schema, audit toàn bộ
> Reader bằng `grep -rn "A_v1\|A.repo\|table('A')"` và migrate đồng
> bộ; nếu phải tồn tại 2 generation thì wrap trong repo
> abstraction trả về union/route theo flag.

### Pattern 2 — JSONB extract operator (`->` vs `->>`)
> **Global Pattern**: `Code build dynamic SQL gán giá trị từ JSONB
> source vào JSONB column dùng operator ->> (returns text)` → 42804
> "expression is of type text". Đúng: dùng `->` (returns jsonb) khi
> target là jsonb; chỉ dùng `->>` khi target là text/number/timestamp.
> Hoặc thêm cast `::JSONB` nhưng chậm hơn vì re-parse.

### Pattern 3 — Mongo BSON Date → PG TIMESTAMP qua JSON
> **Global Pattern**: `Mongo BSON Date được Debezium/JSON serializer
> emit thành JSON number (epoch-ms). Code cast (text)::TIMESTAMP cho
> field này` → 22008 "timestamp out of range" vì PG parse số nhiều chữ
> số như YYYYMMDD. Đúng: branch theo `jsonb_typeof`: nếu number →
> `to_timestamp(value::BIGINT / 1000.0) AT TIME ZONE 'UTC'`; nếu
> string → `::TIMESTAMP`. Tương tự pattern này lặp lại cho mọi
> CDC pipeline lấy data từ Mongo / Kafka Connect Debezium-Mongo.

### Meta-Pattern (lặp lại trong ngày)
> **Global Pattern**: `Service có 2+ DB connection (control / shadow /
> destination plane). Handler X dùng connection mặc định h.db cho
> object thuộc plane khác` → relation/schema not found. Đúng: route
> theo "data plane" của object — nếu DDL/DML chạm shadow object thì
> bắt buộc dùng h.shadowDB. Lặp lại 2 lần cùng ngày 2026-05-13:
> sáng (FixAlterColumnShadowSchema), trưa (FixBatchTransformV2Repo).

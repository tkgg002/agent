## Recommendation: Option B (cluster vào `infra/observability/`)

Sau khi quét cluster cuối + callers (chi tiết §"Audit fact base"), max recommend **Option B**:

> Tạo dir mới `internal/infra/observability/` cho 4 file `system_health_*` (collector + alerts + compute + queries). Sub-dir `internal/infra/observability/probes/` cho 8 probes + 6 test.

**Lý do**:
1. **Semantic fit**: collector + probes = observability stack. `infra/http/` chỉ phù hợp cho `prom_client.go` (HTTP Prometheus); probes có cả DB ping (postgres) + Redis ping (redis) — không thuần HTTP.
2. **Cluster co-locate**: Collector dùng `Snapshot`, `CollectorConfig`, `Status*` constants; alerts/compute/queries đều là method `(c *Collector)` hoặc pure-fn dựa trên `Snapshot`. Co-locate cùng package giảm cross-pkg boundary noise.
3. **Một commit duy nhất**: 1 dir mới, 12+ file move, 2 caller update — vẫn nhỏ enough cho 1 commit "closes Task #19".
4. **Không scope creep**: `infra/http/prom_client.go` để nguyên — debt note "cosmetic re-home" không thuộc đợt J.

**Trade-off**:
- Hơi tốn 1 dir mới `infra/observability/` (vs reuse `infra/http/`). Nhưng pattern hexagonal khuyến khích domain-fit dir naming hơn protocol-fit (HTTP).
- `probes/postgres.go` + `probes/redis.go` không thuần "external HTTP" — nhưng vẫn fit "observability probes" semantically.

**Alternatives đã cân nhắc**:
- **Option A**: `infra/http/probes/` + `infra/observability/` cluster split 2 dir → boundary giữa Collector và probes/ tăng (require import cross-dir).
- **Option C**: Chỉ move probes/, giữ system_health_* trong service/ → không close Task #19 hoàn toàn (service/ vẫn có 7 file).

x2 có quyền pick Option khác nếu thấy Option B sai — final call ở x2.

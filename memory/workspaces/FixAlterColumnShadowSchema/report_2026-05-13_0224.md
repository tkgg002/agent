## Root cause (3 bug độc lập)
1. **Schema-qualification missing** — worker `HandleAlterColumn` build
   `ALTER TABLE "sd_export_jobs"` không có schema → fallback search_path
   → relation not found.
2. **Sai DB connection** — worker dùng `h.db` (destination 5434
   `goopay_dest`) thay vì `h.shadowDB` (5436 `cdc_shadow`) cho shadow
   DDL. Sau khi qualify schema, error chuyển từ `relation does not
   exist` → `schema does not exist` ở DB sai.
3. **Idempotency-key collision** — `BatchUpdate` dispatch 2 commands
   cùng `Idempotency-Key` → table `cdc_jobs` UNIQUE constraint → command
   thứ 2 (alter-column) bị `INSERT ON CONFLICT DO NOTHING` short-circuit
   → KHÔNG publish ra NATS. Chỉ xảy ra khi caller (FE) gửi header
   `Idempotency-Key`.

## Bug bonus (pre-existing, đã fix luôn vì block flow)
4. **`update_mapping_rule.go` query column không tồn tại** — handler
   `SELECT shadow_table FROM cdc_system.mapping_rule_v2` → 42703.
   Column `shadow_table` đã được di trú sang `cdc_system.shadow_binding`
   từ trước nhưng handler chưa update. Hậu quả: rule status không bao
   giờ chuyển sang `approved`. Fix bằng JOIN.

## Lessons cập nhật (đề xuất append vào `agent/memory/global/lessons.md`)
- **Global Pattern**: `A serializes DDL to dest DB X but target schema
  Y belongs to plane Z` → relation/schema not found. Đúng:
  schema-qualify rõ ràng VÀ pick DB connection theo "data plane" của
  object (control plane / shadow plane / destination plane).
- **Global Pattern**: `A queues 2 commands trong cùng request scope với
  shared idempotency key` → table UPSERT `ON CONFLICT DO NOTHING` →
  command thứ 2 silently no-op. Đúng: per-command suffix
  (`:cmdtype`) cho idempotency key khi 1 endpoint dispatch nhiều
  command async.
- **Global Pattern (lặp lại 2026-04-28 + 2026-05-11)**: bare DDL/SQL
  ↔ search_path coupling. Áp dụng cho mọi runtime DDL, không chỉ
  migrations.

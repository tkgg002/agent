## Phase B — Chunksize cho `HandleBatchTransform` — DONE ✅

### Implementation
- **Config**: `WorkerConfig.TransformChunkSize int` thêm vào `config.go`, default 1000 trong 3 YAML.
- **Handler** (`command_handler.go:975-1177`):
  - Thêm field `transformChunkSize int` + setter `SetTransformChunkSize(n)`.
  - Helper `detectPrimaryKey()` query `pg_index + pg_attribute` cho `indisprimary`.
  - Path branching:
    1. `chunk_size <= 0` hoặc table không có single PK → fallback unchunked (1 UPDATE statement).
    2. Có PK → cursor-based chunked loop với `WITH chunk AS (SELECT pk LIMIT chunk_size) UPDATE ... FROM chunk RETURNING s.pk`.
- **Wiring** (`worker_server.go`): `cmdHandler.SetTransformChunkSize(cfg.Worker.TransformChunkSize)` sau khi handler khởi tạo.

### Critical bug avoided (cursor pattern)
Phiên bản đầu tiên (không cursor) có infinite-loop tiềm ẩn: nếu rule generate NULL → SET col=NULL → WHERE `col IS NULL` vẫn match → vòng lặp re-select cùng rows đến `maxIterations=100000`. Fix: thêm `AND pk > lastPK` + `RETURNING s.pk` để track max PK mỗi chunk → monotonic progression, terminate khi chunk trả 0 rows.

### Verification
| Test | chunk_size | input rows | output `rows_affected` | iterations | result |
|------|------------|------------|-------------------------|------------|--------|
| 1 — single-chunk | 1000 | 130 | 130 | 1 | ✅ |
| 2 — multi-chunk | 50 | 175 (reset) | 175 | 4 (50+50+50+25) | ✅ |

Test 2 chứng minh cursor advancement: nếu cursor không hoạt động, hoặc loop dừng sau chunk 1 (50 rows), hoặc loop chạy đến `maxIterations`. Cả hai đều không xảy ra → cursor pattern correct.

## Phase C — Audit `timestamp without time zone` trong `cdc_system` — DONE ✅

### Findings — 15 cột TZ-naive trên 7 bảng

| Table | Column(s) | Usage in Go | Risk |
|-------|-----------|-------------|------|
| `cdc_mapping_rules` | `created_at`, `updated_at` | metadata | LOW |

| `pending_fields` | `detected_at`, `reviewed_at`, `approved_at`, `applied_at` | workflow + `Order("detected_at DESC")` | LOW |
| `schema_changes_log` | `executed_at` | `Order("executed_at DESC")` (read-only audit) | LOW |
| `sources` | `created_at`, `updated_at` | metadata | LOW |

### Gating-critical columns — đã safe
Query expanded cho `next_run_at` / `last_run_at` trên all schemas:
```
cdc_system.cdc_worker_schedule.next_run_at  → timestamptz ✅
cdc_system.cdc_worker_schedule.last_run_at  → timestamptz ✅
cdc_system.transmute_schedule.next_run_at   → timestamptz ✅
cdc_system.transmute_schedule.last_run_at   → timestamptz ✅
```
Bug B pattern (`WHERE next_run_at <= NOW()` + `time.Now().Sub(last_run_at)`) chỉ xảy ra trên schedule tables. Cả hai đã là timestamptz — **không cần migrate thêm** cho Bug B coverage.

### Risk classification rationale
Bug B (TZ-freeze) chỉ trigger khi cột TZ-naive được:
1. Ghi từ Go bằng `time.Now()` (UTC literal).
2. So sánh ngược trong PG với `NOW()` (server local) hoặc trong Go với `time.Now()` (UTC).

15 cột còn lại đều thuộc 3 loại:
- **Audit/metadata** (created_at, updated_at, executed_at): không gating, chỉ display + ORDER BY. Display có thể off bởi TZ offset nhưng không kẹt logic.
- **Workflow timestamps** (reviewed_at, approved_at, applied_at, healed_at): set 1 lần, không so sánh với NOW().
- **ORDER BY** (detected_at, checked_at): so sánh giữa values cùng schema → consistent, không drift.

### Recommendation
Migration sang `timestamptz` cho 15 cột này là **OPTIONAL hygiene**, không phải hotfix:
- Lợi: consistency, ngăn future regression nếu thêm gating logic.
- Cost: ALTER TABLE lock + migration window. Có thể batch với release cycle bình thường.
- Suggested: tạo separate workspace + migration cho hygiene pass, không gộp vào hotfix Bug B.

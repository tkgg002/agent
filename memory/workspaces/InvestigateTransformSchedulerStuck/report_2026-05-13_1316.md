# Report — Vì sao "transform sd_export_jobs OK rows=1" mà worker không thực sự chạy (2026-05-13 13:16 UTC+7)

## TL;DR (kết luận có bằng chứng)
Có **2 bug ĐỘC LẬP** chồng nhau, không phải 1:

1. **Bug A — Telemetry split (fire-and-forget)**: scheduler ghi
   `transform success rows=1` chỉ vì `nats.Publish()` thành công.
   Worker handler thực thi SQL và ghi entry RIÊNG (operation
   `cmd-batch-transform`). Khi worker fail, UI list filter theo
   `operation='transform'` chỉ thấy entry success → user thấy "OK"
   giả.

2. **Bug B — Timezone bug `cdc_worker_schedule.last_run_at`**: cột
   `TIMESTAMP WITHOUT TIME ZONE`. Go ghi wall-clock local (+07), đọc
   lại như UTC → schedule "đông cứng" 7 giờ sau mỗi lần fire. Đây là
   lý do thực sự worker "không chạy" lại từ 09:38 đến giờ điều tra
   (~3.5 giờ, đáng lẽ 1 phút/lần với schedule id=6).

## Bằng chứng (query DB thực tế)

### Bug A — 2 entry tách biệt cho cùng 1 lần fire
```
SELECT id, operation, target_table, status, rows_affected, error_message,
       started_at, triggered_by
FROM cdc_system.cdc_activity_log
WHERE id IN (27, 28);

```
- Cách nhau **56 ms**.
- Entry 27 (scheduler) ghi `success` chỉ vì `nats.Publish` không error.
- Entry 28 (worker handler) là kết quả thực thi SQL, ERROR.
- UI hiển thị filter theo `operation` → user chỉ thấy entry 27.

Source code chứng minh — `worker_server.go:695-716`:
```go
func (s *WorkerServer) runTransformCycle(now time.Time, targetTable string) {
    entries, _ := s.registryRepo.GetAllActive(...)
    dispatched := 0
    for _, entry := range entries {
        if targetTable != "" && entry.TargetTable != targetTable { continue }
        s.nats.Conn.Publish("cdc.cmd.batch-transform", []byte(entry.TargetTable))
        dispatched++
    }
    s.activityLogger.Quick("transform", logTarget, "scheduler", "success",
        int64(dispatched), map[string]interface{}{"tables": dispatched}, "")
}
```
→ `rows_affected = số table đã publish`, KHÔNG phải số row data
được transform.

### Bug B — Timezone freeze schedule

**Snapshot trước experiment** (lúc UTC=06:12):
```
SELECT id, operation, target_table, last_run_at, next_run_at
FROM cdc_system.cdc_worker_schedule WHERE id IN (2,6);

 id | operation | target_table   | last_run_at                | next_run_at
  2 | transform |                | 2026-05-13 09:29:22.74273  | 2026-05-13 09:34:22.74273
  6 | transform | sd_export_jobs | 2026-05-13 09:38:22.743849 | 2026-05-13 09:39:22.743849
```
- Schema: `last_run_at | timestamp without time zone` (verified
  via `\d cdc_system.cdc_worker_schedule`).
- PG `now() AT TIME ZONE 'UTC' = 06:12:17`. Stored value `09:38:22` (no TZ)
  = local clock UTC+7.
- Khi GORM đọc no-TZ TIMESTAMP, gán Location=UTC → time `09:38:22 UTC`
  (lệch +7h vào tương lai).
- Gating logic `worker_server.go:624-633`:
  ```go
  intervalDur := time.Duration(sched.IntervalMinutes) * time.Minute
  if sched.LastRunAt != nil && now.Sub(*sched.LastRunAt) < intervalDur {
      continue
  }
  ```
  `now.Sub(lastRunAt) = 06:12 - 09:38 = -3h26m`. Negative duration
  `< 1min` → continue → skip mỗi tick.

**Experiment reproduce** (set lastRunAt=NULL → đợi 65s):
```
UPDATE cdc_system.cdc_worker_schedule SET last_run_at = NULL WHERE id = 6;
-- 65s later:
SELECT id, last_run_at, run_count FROM cdc_system.cdc_worker_schedule WHERE id=6;
 id | last_run_at                | run_count
  6 | 2026-05-13 13:13:09.791229 | 2

SELECT id, operation, status, rows_affected, started_at FROM cdc_system.cdc_activity_log
WHERE operation IN ('transform','cmd-batch-transform') AND target_table='sd_export_jobs'
ORDER BY id DESC LIMIT 4;

 id | operation           | status  | rows | started_at
 52 | cmd-batch-transform | success | 130  | 2026-05-13 06:13:10.035+00
 51 | transform           | success |   1  | 2026-05-13 06:13:09.800+00
 34 | cmd-batch-transform | success | 129  | 2026-05-13 03:01:02.720+00
 33 | cmd-batch-transform | error   |   0  | 2026-05-13 02:57:56.323+00
```
- Schedule fire NGAY tick kế (60s) sau khi NULL hoá lastRunAt.
- Entry 51 (scheduler) + entry 52 (worker handler success rows=130).
- Worker hoạt động ĐÚNG (rows=130 transform thành công).
- **Nhưng** new `last_run_at = 13:13:09` (local UTC+7) → schedule
  sẽ tiếp tục đông cứng đến `13:13 UTC actual` = `20:13 local`,
  tức ~7h kế tiếp.

## Chưa fix code (theo yêu cầu user "chỉ làm đúng yêu cầu" = chỉ document)

### Suggest fix Bug A (chọn 1)
- **Đơn giản**: đổi status scheduler entry từ `success` → `accepted`
  cho rõ semantic; rows = số table queued.
- **Đầy đủ**: implement `cdc.evt.batch-transform.completed` + monitor
  riêng update entry scheduler theo evt (3-actor pattern lesson 1297).

### Suggest fix Bug B (chọn 1)
- **Recommend**: migration đổi cột `cdc_worker_schedule.{last,next}_run_at,
  created_at, updated_at` từ `timestamp` → `timestamptz`. Cần dùng
  `AT TIME ZONE 'Asia/Ho_Chi_Minh'` để dịch data hiện tại về đúng
  instant trước khi convert.
  ```sql
  ALTER TABLE cdc_system.cdc_worker_schedule
    ALTER COLUMN last_run_at TYPE timestamptz
      USING last_run_at AT TIME ZONE 'Asia/Ho_Chi_Minh',
    ALTER COLUMN next_run_at TYPE timestamptz
      USING next_run_at AT TIME ZONE 'Asia/Ho_Chi_Minh',
    ALTER COLUMN created_at  TYPE timestamptz
      USING created_at  AT TIME ZONE 'Asia/Ho_Chi_Minh',
    ALTER COLUMN updated_at  TYPE timestamptz
      USING updated_at  AT TIME ZONE 'Asia/Ho_Chi_Minh';
  ```
- **Tạm thời**: Go luôn `time.Now().UTC()` khi ghi và `.UTC()` khi
  đọc — không bền, dễ regress.

## Lessons mới (đề xuất append vào `agent/memory/global/lessons.md`)

### Pattern 1 — Fire-and-forget telemetry split
> **Global Pattern**: `Scheduler / publisher A ghi activity_log với
> status=success ngay sau khi nats.Publish/queue.Send (in-memory
> enqueue). Handler B execute thực sự ghi entry RIÊNG với operation
> name khác. UI filter theo operation chỉ thấy entry A → user thấy
> "OK" giả khi B fail`. Đúng: A ghi `accepted` (không phải `success`),
> hoặc subscribe evt completion từ B để cập nhật entry A. Tham chiếu
> lesson 1297 (3-actor pattern publisher → handler → monitor).

### Pattern 2 — TZ-naïve TIMESTAMP + Go local clock = silent freeze
> **Global Pattern**: `Cột PostgreSQL X kiểu TIMESTAMP WITHOUT TIME
> ZONE. Go service ghi bằng time.Now() (Location=Local). Driver strip
> TZ → PG store wall clock local. GORM đọc lại gán Location=UTC →
> giá trị nhìn như "+N giờ trong tương lai UTC". Logic so sánh
> now.Sub(stored) trả Duration âm, nếu code check < threshold thì
> skip → freeze N giờ`. Đúng: dùng `timestamptz` cho mọi cột thời
> gian được scheduler/poller compare; hoặc nhất quán
> `.UTC()` khi ghi VÀ đọc; thêm test có offset không phải UTC để
> phát hiện sớm.

## (3) Unify Kafka batch threshold 100 → config-driven

### Trước
```go
// kafka_consumer.go:360
if batch.processed >= 100 {
    kc.flushBatch(msg.Topic)
}
```

### Sau
```go
// kafka_consumer.go:367-374
flushAt := kc.batchFlushSize
if flushAt <= 0 {
    flushAt = 100
}
if batch.processed >= flushAt {
    kc.flushBatch(msg.Topic)
}
```

### Wiring

|---|---|

**Zero regression**: default 100 = giá trị hardcode cũ. Behavior không đổi nếu YAML không override.

## Lesson cần ghi (sẽ append vào `agent/memory/global/lessons.md`)

**Global Pattern [A applies DB schema change S via runtime psql / direct exec → B reports done] → Pitfall Y khi target environment E re-initializes**:
- Schema mutations qua `docker exec psql` / runtime ad-hoc tools KHÔNG persist trong migration repo → bất kỳ E rebuild (wipe + reseed, fresh deploy, DR restore) sẽ rollback về schema cũ → bug đã fix tái xuất.

- Liên quan lesson 803 (migration persist) + 1228 (migration sau start service). Mở rộng: không chỉ index, mọi schema mutation phải qua repo.
